🐛 ISSUE REPORTED:
═══════════════════════════════════════════════════════════════════════════

User uploads profile picture and clicks Save. After logging out and logging 
back in, the profile picture disappears.


🔍 ROOT CAUSE ANALYSIS:
═══════════════════════════════════════════════════════════════════════════

The issue was in the image URL construction logic in UserProfile.tsx.

**Problem:**
- Profile pictures are stored in the database as resource paths (e.g., "resources/uid_100020016/xyz.png")
- When displaying, the code needs to construct the full URL by prepending the CDN domain
- The previous logic wasn't handling all cases correctly:
  * During upload: Used blob preview URL ✓
  * After save but before logout: Used blob preview URL (still in memory) ✓
  * After logout and login: Preview URL is gone, needs to construct from DB path ✗

**The Bug:**
Line 258 (old code):
```javascript
src={profilePictureUpload.previewUrl || `https://grazia-prod.oss-ap-southeast-1.aliyuncs.com/${formData.profile_picture}`}
```

This worked MOST of the time, but had edge cases:
- If profile_picture was already a full URL (shouldn't happen but could)
- Didn't properly handle empty/null cases
- No logging to debug issues


✅ THE FIX:
═══════════════════════════════════════════════════════════════════════════

**1. Added Helper Function: getProfilePictureUrl()**

Location: UserProfile.tsx, after fetchProfileData function

```typescript
// Helper function to get the full profile picture URL
const getProfilePictureUrl = () => {
  // If there's a preview URL (during upload), use it
  if (profilePictureUpload.previewUrl) {
    return profilePictureUpload.previewUrl;
  }
  
  // If there's a profile picture stored
  if (formData.profile_picture) {
    // Check if it's already a full URL
    if (formData.profile_picture.startsWith('http://') || 
        formData.profile_picture.startsWith('https://')) {
      return formData.profile_picture;
    }
    // Otherwise, construct the full URL from the resource path
    return `https://grazia-prod.oss-ap-southeast-1.aliyuncs.com/${formData.profile_picture}`;
  }
  
  return null;
};
```

**Benefits:**
✓ Handles preview URL (blob:// during upload)
✓ Handles resource path from database
✓ Handles full URLs (defensive programming)
✓ Handles null/empty cases
✓ Single source of truth for URL logic
✓ Easier to debug and maintain


**2. Updated Image Display to Use Helper**

Old code:
```tsx
{profilePictureUpload.previewUrl || formData.profile_picture ? (
  <img src={profilePictureUpload.previewUrl || `https://grazia-prod.oss-ap-southeast-1.aliyuncs.com/${formData.profile_picture}`} />
) : (
  <User className="w-16 h-16 text-muted-foreground" />
)}
```

New code:
```tsx
{getProfilePictureUrl() ? (
  <img src={getProfilePictureUrl()!} />
) : (
  <User className="w-16 h-16 text-muted-foreground" />
)}
```

**Benefits:**
✓ Cleaner, more readable code
✓ Consistent URL handling
✓ Easier to update logic in one place


**3. Added Debug Logging**

Added console.log statements to track data flow:

In fetchProfileData:

In handleUpdate:

**Benefits:**

✓ Helps diagnose future issues

**Issue 2: Picture disappears after logout/login (MAIN FIX)**

📊 DATA FLOW:
═══════════════════════════════════════════════════════════════════════════

**Upload Flow:**
1. User selects file
2. Frontend validates file (size, type)
3. Call edge function to get presigned URL
4. Edge function returns: {upload_url, resource_path}
5. Frontend uploads file directly to CDN using presigned URL
6. On success, update formData.profile_picture = resource_path
7. User clicks Save
8. Frontend saves formData to database (people table)
9. Database stores: profile_picture = "resources/uid_xxx/yyy.png"

**Load Flow (After Login):**
1. User logs in successfully
2. Navigate to User Profile
3. fetchProfileData() called
4. Query database for person data by person_id
5. Receive profile_picture = "resources/uid_xxx/yyy.png"
6. Set formData.profile_picture
7. Render image with getProfilePictureUrl()
8. Helper constructs: "https://grazia-prod.oss-ap-southeast-1.aliyuncs.com/resources/uid_xxx/yyy.png"
9. Browser loads image from CDN
10. Image displays in circular frame
